THE THINKING BEHIND THE PAGES / OCTOBER 28, 2026

A student first.
A system second.

A heuristic review of the existing student demo, used to guide the local workbook interface and its connection to the existing controller. These are design hypotheses, not findings from interviews or usability sessions with students.

01 · Make the next step obvious.

The existing demo offers another attempt after every result, including passes, with no retry limit. The new design uses Learn → Practice → Reflect, then a clear summary. Below 8/10, students can revisit missed lesson sections. The workbook now connects to the real controller: below 8/10 it prepares the one focused retry and ends with a saved summary after that retry, whatever the score. In offline mode, retry fixtures may repeat questions; live mode uses the existing reviewed generation path. Offline behavior is not evidence of live question quality.

02 · Let the student keep their place.

Native radio inputs replace visual-only selected buttons. Choosing an answer does not rebuild the page or reset focus. Students can navigate all ten questions, return to the explanation, review choices before submitting, and resume a sample draft on this browser when storage is available.

03 · Give the content room.

Paper-like pages, blue ink, red margin notes, a narrow reading column, generous sans-serif body text, and a larger-text control support reading. Serif chapter titles, subtle ruled paper, chapter tabs, and restrained borders give the interface a student-book character. Decoration is static and content stays readable. Mobile layouts put the lesson and answers before secondary navigation.

04 · Make feedback useful, not personal.

Missed answers come first, with the chosen answer, correct answer, and sample rationale. Results describe this attempt, without claiming to know reasoning or lasting mastery. “Revisit” replaces punitive language. Source attribution stays available.

05 · Be honest about the prototype.

The sample label is visible from the start. The interface now sends answers to the existing backend controller. SQLite stores attempts, feedback, one retry and summaries. Unanswered quizzes omit keys; correct answers appear only after submission. Local HTTP checks validate Host, Origin and a server-generated action token. This is one local profile, not real student authentication. The page explicitly labels its server-selected mode. Live mode uses real Tutor, Assessment and Reviewer adapters with paid calls only after user actions; offline mode keeps fixture content and synthetic review. A live review failure never falls back to a fixture. Opening the page is read-only. Original static sample and private database paths are not served by the workbook HTTP layer.

The visual brief.

The requested references are Apple, The New York Times, and Vogue, combined with Art Deco geometry. The initial interpretation used an editorial masthead and an original bilayer illustration; the current version adds a student-workbook structure with paper surfaces, blue text and red margin accents. No logos, photographs or page layouts were copied. Apple and Vogue reference pages were consulted; the New York Times page was unavailable to the research tool.

What still needs checking with students?

Ask a student to find the lesson, read a concept, select and change an answer with the keyboard, return after a refresh, explain the score, and find what to revisit. Check whether the editorial styling improves focus or feels too formal. Observe completion and confusion before making preference claims.

Connected locallyThe HTTP layer reuses start, quiz retrieval, answer submission, feedback, routing, reteaching, retry and summary actions. Stable request IDs, server grading, publication checks and owned session reads stay in the backend. Dedicated integration tests verify key exclusion, pass/retry completion, persistence, duplicate requests, ownership, and request-boundary checks. No agents or versioned contracts were added; wiring tests use stubbed providers; no fresh paid live session was started by the assistant. The reading page renders the actual saved Tutor text, and live/fixture progress is kept separate.
